# ⚙️ n8n
n8n = herramienta de automatización visual. Unís cajitas (nodos) y armás un flujo (workflow) que conecta sistemas sin escribir todo el código. Parecido a Zapier o Make, pero **open source** (código abierto) y se puede instalar en servidores propios (*self-hosted*). ← [[00 - Índice]]

## Piezas
- **Workflow**: el flujo completo.
- **Nodo**: cada paso (leer un mail, llamar una API, escribir en una planilla).
- **Trigger**: el nodo que arranca el flujo:
  - **Webhook**: otro sistema te llama.
  - **Schedule/Cron**: corre a una hora fija.
  - **App trigger**: por ejemplo, "llegó un mail nuevo".
- **Items**: n8n pasa los datos como una **lista de objetos JSON**. Cada nodo procesa cada item.
- **Expresiones**: `{{ $json.email }}` toma un campo del item actual.
- **Credentials**: las claves se guardan aparte, nunca dentro del nodo.

## Nodos que tenés que nombrar
| Nodo | Para qué |
|---|---|
| **HTTP Request** | Llamar cualquier API (el comodín) |
| **Webhook** | Recibir llamadas |
| **IF / Switch** | Decidir caminos |
| **Merge** | Juntar dos ramas |
| **Code** | Escribir JS/Python cuando lo visual no alcanza |
| **Split in Batches / Loop** | Procesar de a tandas (por rate limits) |
| **AI Agent / LLM** | Usar un modelo dentro del flujo |
| **Error Trigger** | Flujo que se dispara cuando otro falla |

## Buenas prácticas (lo que suena senior)
- **Manejo de errores:**
  - "Retry on fail" (reintentar automáticamente).
  - Error workflow que avisa por Slack o mail.
  - DLQ manual: guardar los fallidos para reprocesar.
- **Idempotencia:** si el flujo corre 2 veces, no duplica (chequear "¿ya existe?" antes de crear).
- **Subworkflows:** partir flujos grandes en piezas reutilizables ("Execute Workflow").
- **Versionado:** exportar workflows como JSON a Git.
- **Secretos** en Credentials o variables de entorno.
- **Cuándo NO usar n8n:** volúmenes enormes o lógica muy compleja. Ahí conviene un servicio en código o un pipeline ([[06 - Pipelines]]).

## Ejemplo de RR.HH. para contar
> Llega una solicitud de licencia por formulario (**Webhook**) → **IF** según el tipo → **HTTP Request** al sistema de RR.HH. para ver los días disponibles → **LLM** resume el pedido para el líder → mensaje a Slack con botones aprobar/rechazar → **Error Trigger** avisa si algo falla.
